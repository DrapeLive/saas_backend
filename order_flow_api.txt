ORDER FLOW API
==============

Authentication
--------------
All endpoints require:
Authorization: Bearer <JWT access token>

Agent endpoints require an authenticated AGENT. Agents can only access their
own orders. The existing /api/orders/<id>/items/ endpoints remain supported;
the explicit add-item and remove-item URLs below are aliases for mobile clients.

1. Create a draft
------------------
POST /api/orders/
Body:
{
  "customer": "<customer UUID>",
  "delivery_address_line1": "Optional address",
  "delivery_city": "Optional city",
  "delivery_state": "Optional state",
  "delivery_pincode": "Optional pincode",
  "order_notes": "Optional notes"
}

Response: 201
{
  "id": "<order UUID>",
  "status": "draft",
  "customer": "<customer UUID>",
  "items": [],
  "draft_expires_at": "2026-11-05T16:30:00Z",
  "seconds_until_expiry": 2700,
  "total_amount": "0.00"
}

The draft is valid for 45 minutes. The expiration timer is not reset when the
draft is viewed. It is refreshed only when draft activity changes its contents.

2. List drafts
--------------
GET /api/orders/drafts/

Response: 200
{
  "count": 1,
  "results": [
    {
      "id": "<order UUID>",
      "status": "draft",
      "customer": "<customer UUID>",
      "customer_name": "Customer Name",
      "created_at": "2026-11-05T15:45:00Z",
      "draft_expires_at": "2026-11-05T16:30:00Z",
      "seconds_until_expiry": 2700,
      "item_count": 2,
      "total_amount": "2500.00",
      "items": []
    }
  ]
}

The current response serializer exposes draft summaries. Use the continue
endpoint for full item details.

3. Continue a draft
--------------------
GET /api/orders/{order_id}/continue/

Response: 200
Returns the complete OrderDetail response, including customer_details, items,
variant_details, size, quantity, unit_price, line_total and
seconds_until_expiry.

Expired drafts return 409:
{"detail": "This draft order has expired.", "code": "DRAFT_EXPIRED", ...}

4. Add an item
--------------
POST /api/orders/{order_id}/add-item/
Also supported:
POST /api/orders/{order_id}/items/

Body:
{
  "color_variant": "<color variant UUID>",
  "size_range": "20-24",
  "quantity": 2,
  "discount_pct": "0.00",
  "client_ref": "optional-idempotency-key"
}

Response: 201 for a new group, 200 for a repeated client_ref:
{
  "order": {"id": "<order UUID>", "status": "draft", "items": [...]},
  "group_id": "<group UUID>",
  "stock_updates": [
    {
      "variant_size_id": "<variant size UUID>",
      "stock_quantity": 10,
      "reserved_qty": 2,
      "available_qty": 8
    }
  ],
  "created": true
}

The item is validated and reserved atomically. Items cannot be added after
submission, cancellation or expiration.

5. Remove an item
-----------------
DELETE /api/orders/{order_id}/remove-item/{order_item_id}/
Also supported:
DELETE /api/orders/{order_id}/items/{order_item_id}/

Optional query: ?scope=group (default) or ?scope=single.

Response: 200:
{"order": {...updated draft...}, "stock_updates": [...]}

Removing the final item releases its reservation and deletes the parent draft
from PostgreSQL. The response still contains the deleted order snapshot with an
empty items array so existing clients can update their local state.

6. Submit a draft
-----------------
POST /api/orders/{order_id}/submit/
Body:
{
  "order_notes": "Optional final notes",
  "discount_pct": "0.00"
}

Response: 200:
Returns the complete submitted order with status "submitted".

The server locks the order row and all required variant rows, validates that
the draft is not expired and contains items, calculates totals, and prevents
further draft changes.

7. Delete a draft
-----------------
DELETE /api/orders/{order_id}/

Response: 204 No Content

Only the owning agent can delete a DRAFT. Reservations are released and order
items/status history are deleted through the existing database relationships.
Submitted and later lifecycle states cannot be deleted through this endpoint.

Automatic expiration
--------------------
Celery Beat periodically calls the existing draft cleanup task. PostgreSQL is
the source of truth: expired rows are selected by status=draft and
draft_expires_at <= current time, then locked and rechecked before deletion.
The cleanup task never deletes submitted orders. Redis is used by existing
Celery infrastructure/realtime delivery only; draft persistence and expiration
correctness do not depend on Redis.

Error responses
---------------
404: order, customer, item, variant or color variant not found.
409: expired draft, insufficient stock, invalid lifecycle state, or blocked
customer.
400: invalid request body or quantity.
403: authenticated user lacks the required role or ownership.
